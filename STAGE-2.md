# Stage 2 — Implementation Specification

Storage `TreeMap[str, SupportCase]`: owner, product_id, version, edition, region, policy_url, support_start/end, state, outcome, evidence_digest, retry_count:u8. API: `register_case`, `freeze_case`, `assess`, `retry_unresolved`, views. Validate bounded semver, exact product and HTTPS. Leader/validator independently extract inclusive/exclusive version bounds, edition/region lists and dates; compare outcome fields. WRONG: `if version >= minimum: SUPPORTED`. CORRECT: evaluate all version, edition, region and date bounds. Test start/end boundaries, excluded edition/region, malformed version, unavailable source, disagreement, schema and Studio E2E.

Revision 2 predicate order: canonical product mismatch -> `UNRESOLVED`; edition/region exclusion -> `POLICY_EXCLUDES_EDITION` (rename in implementation to `POLICY_EXCLUDES_SCOPE`); malformed/missing policy fields -> `POLICY_SCOPE_UNCLEAR`; outside inclusive version/date window -> `OUT_OF_SUPPORT`; otherwise `SUPPORTED`. Recheck exact bounds, prerelease/build/abbreviated/malformed versions, before/on/after dates and all exclusion combinations. Duplicate audit must specifically prove vendor lifecycle evidence + operational support-date readback differs materially from applicability projects. Parser/storage/web/serialization/disagreement probe precedes lock.
